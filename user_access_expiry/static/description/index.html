User Access Expiry Date

Contractors lose access on schedule. Automatically.

Offboarding shouldn't depend on someone remembering. Set an end date on any user account — contractors, interns, auditors, temporary staff — and a daily job archives it the moment the date passes. Clean audit trail, admin notification, zero configuration. Free and open source (LGPL-3), identical behavior on Odoo 14.0 through 19.0.

  • Zero config — setting the date is the whole setup.
  • Safe by design — administrators, OdooBot and the superuser are never archived, even with a past date.
  • Audit trail — archived accounts carry a "Deactivated by Expiry" flag and timestamp.
  • No surprises on rehire — re-activating a user clears the stale date so they are not re-archived the next night.
  • Admin summary email on every archival run (can be turned off).

Installation

  1. Open Apps, remove the default "Apps" filter if needed, and search for User Access Expiry Date.
  2. Click Install. Only standard Odoo modules (base_setup, mail) are required.

Configuration

  1. None required — setting a date on a user is the whole configuration.
  2. Optional: in Settings → General Settings, Users section, toggle Notify on Access Expiry (administrator email summary, on by default).

Usage

  1. Open a user (Settings → Users), go to the Access Expiry tab and set the Access Expiry Date — e.g. the contractor's end date.
  2. The daily scheduled action "Users: deactivate expired accounts" archives the account once the date passes; the tab then shows the audit flag and exact timestamp.
  3. Filter the users list with Has Expiry Date or Deactivated by Expiry to review upcoming and past expiries.
  4. Re-activating an archived user clears the audit flags and the stale date.

Version notes

Behavior is identical on every supported series (14.0 – 19.0). Only internal view markup differs per version.
